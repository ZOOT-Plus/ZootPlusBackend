# 干员养成推荐

页面 `/recommendations` 通过 `GET /copilot/recommendations` 统计公开且未删除的 PRTS 自动作业，根据作者填写的需求给出干员养成建议。

推荐包含精英化、等级、技能、技能等级和模组类型，并展示作业来源与数据完整程度。默认关注近期有独立打法支持的干员，也可以按常驻关卡、指定关卡或活动筛选，或查看历史参考。

## 查询

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `scope` | `RECENT` | 近期通用；`PERMANENT` 为常驻关卡；`HISTORY` 为历史参考 |
| `days` | `180` | 近期窗口天数；0 表示历史模式不限时间，默认推荐仍使用 180 天的近期窗口 |
| `coverage` | `0.8` | 每个技能、模组分支的加权需求覆盖目标；页面提供 0.6、0.8、0.9 |
| `stageId`、`category`、`activity` | 空 | 关卡、类型、活动或章节 |
| `includeClosed` | `false` | 包含服务器标记已关闭的活动；开放状态未知的关卡默认保留 |
| `includeAlternatives` | `true` | 包含群组备选 |
| `includeUncertain` | `false` | 近期模式中展示支持不足的干员，并纳入零评价的待观察作业 |

常驻关卡由 `ArkLevelType` 判定，包括主线、资源收集和剿灭。常驻模式保留窗口内有新打法或近期评价的内容。近期通用模式会参考历史常驻需求生成练度目标，榜单候选仍需满足近期支持条件。关卡开放状态使用已有同步数据。

干员按官方名称和职业解析；同名干员需要填写职业才能区分。解析时过滤未识别干员、非法练度和损坏的 JSON。模组值 `-1` 表示不指定模组。旧版 v2 模组索引按对应干员的原始模组顺序转换，越界或缺少映射的索引会被过滤。

## 独立打法

先按关卡、难度和动作结构分组，再将干员集合与组内各簇的首份作业比较。Dice 相似度达到 0.85 时归入同一簇，计为一个独立打法。动作结构保留顺序、执行主体位置、部署坐标、朝向和点击、滑动、镜头目标。无动作数据时按相同阵容合并，说明、颜色和延时变化归在同一打法内。

养成要求或执行条件不同的作业保留为簇内变体。同一变体选评价数最多的作业作为反馈来源，同票时选 ID 最小的作业，赞踩和浏览量均取自这一份来源。每个簇的证据权重平均分给其变体。

簇的发布时间取所有副本中最早的首次发布时间，编辑时间 `uploadTime` 不参与年龄计算。相似性比较仅在同一动作结构组内进行，明显改写的脚本可能形成新的独立打法。

## 权重和近期支持

- 质量使用原始好评、差评数的 Wilson 95% 区间下界。区间上界小于 0.6 的作业被排除；纳入待观察数据时，零评价作业获得 0.05 的权重。
- 成熟度为 `0.25 + 0.75 × min(发布后小时数 / 72, 1)`。
- 时效按 180 天半衰期衰减。质量下界达到 0.5 且有近期正面评价时，取发布年龄与评价年龄加 90 天中的较小值。评分表保存当前评价的最后修改时间。
- 曝光以同关卡、同年龄区间的对数浏览量中位数为基准，修正幅度限制在 0.9～1.1。赞踩比例的分母为好评与差评之和。

群组按原始备选条目数平均分配一个位置的贡献。无法解析的成员只失去自身份额，其他成员的份额保持原值。单成员群组也保留备选标记，关闭包含群组备选时会被排除。同一作业内，同一干员仅保留最大的出场份额。

贡献先除以关卡内独立打法数，再按活动或章节和关卡类型平衡。常驻内容与其他内容分别统计分类，总预算分别为 0.3、0.7；其中一类为空时，另一类使用完整预算。质量权重在平衡后保留。

默认候选需要近期至少两个关卡、三个独立打法支持；指定关卡或活动时，一个可靠打法即可。每簇取一份有效评价汇总，Wilson 下界达到 0.5 才满足置信条件。只有历史支持的干员可在历史模式查看。结果状态分为近期适用、范围有限、历史适用和反馈不足。

算法版本 1 使用上述参数。调整参数时，用复制、冷门关卡、新发布作业和历史干员等案例检查结果。

## 养成目标

按技能编号和模组类型划分分支，根据来源中的精英化、等级和技能等级要求构造可行配置，并满足技能和模组的解锁条件。达到分支内目标覆盖率后，只保留各维度无法再降低的配置；无法比较高低的配置并列返回。技能 8～10 级对应专精一～三。

每个分支展示需求占比、覆盖率，以及精英化与等级、技能等级、模组类型的数据完整率。来源中缺失的字段保持未知，覆盖率按已注明的需求计算。

模组建议包含类型，`TrainingTarget.moduleLevel` / 前端 `moduleLevel` 保持为空。

## 数据和缓存

Caffeine 缓存一个公开数据快照，15 分钟过期。首次请求或结构快照失效后，后端分批读取全部公开自动作业，完成 JSON 解析、动作指纹生成和打法归并。不同筛选查询复用这些结果，按各自选集计算权重、曝光基线和练度目标；每个快照保存最多 64 组查询结果。

上传、编辑、删除、公开状态、关卡同步，以及活动和危机合约开放状态变化会使结构快照失效。评分变化只重读对应作业的反馈，更新相关打法的代表来源，并替换查询结果缓存。评分未变、通知或评论开关变化时保留缓存。评分更新沿用快照原来的统计时间和过期时间，浏览量随评分刷新或快照重建更新。

快照创建、更新和失效共用锁，不同查询并发计算，相同查询复用计算结果。计算中的请求使用取得的快照；更新后，新请求使用新的查询缓存。接口响应使用 HTTP `no-store`。

干员目录使用前端已有的生成数据。更新前端干员数据后，在后端根目录运行：

```sh
node scripts/update-recommendation-catalog.mjs ../zoot-plus-frontend/src/models/generated/operators.json
```

## 本地手动测试

空库可用 `scripts/seed-recommendation-demo.sql` 导入 10 条带 `[手动测试]` 标记的作业和 5 个模拟关卡，赞踩数也是样例数据。

在后端根目录执行：

```sh
docker exec -i postgres psql -U zoot_dev -d zoot_dev -v ON_ERROR_STOP=1 < scripts/seed-recommendation-demo.sql
```

脚本要求数据库名为 `zoot_dev`，重复执行会保留已有样例。数据库直接导入后，重启后端以更新缓存，再刷新页面：

```sh
./gradlew bootRun --args='--spring.profiles.active=dev'
```

在前端根目录启动开发服务器：

```sh
VITE_API=http://127.0.0.1:8848 pnpm dev --host 127.0.0.1 --port 5173
```

打开 `http://127.0.0.1:5173/recommendations`，每项检查前先重置筛选：

| 操作 | 预期结果 |
| --- | --- |
| 默认筛选 | 显示银灰，近期支持为 3 个关卡、3 个独立打法；复制版归入原打法 |
| 展开银灰详情 | 显示无模组与 X 模组分支；X 分支为精二 90 级、三技能专三，模组等级为空 |
| 选择历史参考、全部时间 | 显示棘刺，状态为历史适用 |
| 勾选包含待观察干员 | 显示山，状态为反馈不足 |
| 选择测试-1 关卡 | 显示夜莺，来源中精英化、等级和技能等级字段缺失 |
| 选择测试-4 关卡，再勾选包含已关闭内容 | 显示能天使；未勾选时该关卡的结果为空 |
| 选择测试-5 关卡 | 显示阿米娅和能天使；关闭包含群组备选后结果为空 |
| 查看历史模式，包括待观察数据 | 史尔特尔因低好评被排除 |
| 点击银灰的代表作业 | 跳转到标有 `[手动测试]` 的作业详情 |
| 切换语言、主题、手机宽度，复制筛选后的 URL | 页面可读，筛选条件可恢复 |

样例作业 ID 为 `900000001`～`900000010`，模拟关卡 ID 为 `recommendation_demo_1`～`recommendation_demo_5`。
