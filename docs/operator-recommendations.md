# 干员养成推荐

页面 `/recommendations` 通过 `GET /copilot/recommendations` 统计公开且未删除的 PRTS 自动作业，根据作者填写的需求给出干员养成建议。

定位为日常养成工具，帮助用户参考近期需求、补齐常驻关卡练度或准备指定活动和关卡。结果包括精英化、等级、技能、技能等级和模组类型，并列出作业来源和数据完整程度；不结合个人持有干员、已有练度或资源成本计算培养优先级。

默认展示用途、关卡类型、活动与关卡，以及本地干员搜索、职业和星级筛选。近期窗口、培养目标和证据开关折叠在“更多条件”，默认使用 180 天、0.8 覆盖目标。带有非默认条件的旧链接会自动展开更多条件。长期参考使用当前快照中收录的旧作业，不提供过去时点的回放或任意日期区间分析。

## 查询

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `scope` | `RECENT` | 近期通用；`PERMANENT` 为常驻补课；`HISTORY` 为长期参考 |
| `days` | `180` | 近期支持窗口，仅支持 90、180、365；长期参考另支持 0（不限窗口），页面默认 0。其他用途的 0 兼容为 180，常驻补课统一使用 180 判断近期状态 |
| `coverage` | `0.8` | 每个技能、模组分支的加权需求覆盖目标，仅支持 0.6、0.8、0.9；并非通关成功率或资源预算 |
| `stageId`、`category`、`activity` | 空 | 关卡、类型、活动或章节 |
| `minOperationCount` | `5` | 活动和关卡下拉选项的最低作业数，仅支持 1、5、10；只影响选项，不作为推荐样本量门槛，也不限制显式指定的查询 |
| `includeClosed` | `false` | 包含服务器标记已关闭的活动；开放状态未知的关卡默认保留 |
| `includeAlternatives` | `true` | 包含群组备选 |
| `includeUncertain` | `false` | 近期模式中展示支持不足的干员，并纳入零评价的待观察作业 |

常驻关卡由 `ArkLevelType` 判定，包括主线、资源收集和剿灭。常驻补课保留较早的需求，按现有质量规则过滤和标注反馈状态，缺少近期支持的可靠结果显示为历史适用。常驻补课不展示时间与开放状态开关。近期通用模式会参考历史常驻需求生成练度目标，榜单候选仍需满足近期支持条件。近期窗口同时考虑新打法和近期正面评价，不等同于发布时间过滤。关卡开放状态使用已有同步数据。

接口拒绝非预设的数值（包括非有限覆盖率）、超长文本和不在当天推荐目录中的分类、活动或关卡；互相矛盾的归属关系也返回 400。关卡 ID 与 levelId 别名忽略大小写和首尾空白，唯一目录项的别名统一为 stageId，使等价条件共用缓存。多个目录条目共用 stageId 时，保留指向单个条目的 levelId，避免扩大查询范围；不自动填充用户未选择的父级条件。常驻补课的无效时间差异与开放状态开关不产生额外缓存键。页面将不支持的旧链接数值归一为默认预设。

干员按官方名称和职业解析；同名干员需要填写职业才能区分。解析时过滤未识别干员、非法练度和损坏的 JSON。模组值 `-1` 表示不指定模组。旧版 v2 模组索引按对应干员的原始模组顺序转换，越界或缺少映射的索引会被过滤。

关卡只关联目录中 `stageId` 非空的记录。匹配时忽略大小写和首尾空白，优先使用 `stageId`、`levelId`；使用编号或中文名时，必须能唯一确定关卡。普通与突袭变体共用别名时优先关联普通关卡，明确填写的变体 ID 仍单独处理。无法匹配或因重名无法确定关卡的作业会被排除，并计入 `invalidCount`。活动、类型和关卡筛选项都使用关联后的目录信息，关卡按真实 `stageId` 去重。危机合约目录中以 `level_` 开头的内部编号不列入活动选项。

选项计数只统计当前 `scope`、`days` 和 `includeClosed` 范围内成功解析的公开自动作业。同一独立打法的多份作业分别计数。活动按名称汇总，并受 `category` 限制；关卡按 `stageId` 汇总，并受 `category`、`activity` 限制。选择活动或关卡不会把同级候选列表限制为当前选中项。只要活动的作业总数达到门槛，即使其中每个关卡的作业数都未达到门槛，仍可选择该活动。

例如，`GET /copilot/recommendations?minOperationCount=10` 只列出至少有 10 份作业的活动和关卡；页面链接 `/recommendations?minOperationCount=10` 会将同名参数传给接口。设为 `1` 时，当前范围内至少有一份作业的活动和关卡都会列出。

## 独立打法

先按关卡、难度和动作结构分组，再将干员集合与组内各簇的首份作业比较。Dice 相似度达到 0.85 时归入同一簇，计为一个独立打法。动作结构保留顺序、执行主体位置、部署坐标、朝向和点击、滑动、镜头目标。无动作数据时按相同阵容合并，说明、颜色和延时变化归在同一打法内。

养成要求或执行条件不同的作业保留为簇内变体。同一变体选评价数最多的作业作为反馈来源，同票时选 ID 最小的作业，赞踩和浏览量均取自这一份来源。每个簇的证据权重平均分给其变体。

簇的发布时间取所有副本中最早的首次发布时间，编辑时间 `uploadTime` 不参与年龄计算。相似性比较仅在同一动作结构组内进行，明显改写的脚本可能形成新的独立打法。

## 权重和近期支持

- 质量使用原始好评、差评数的 Wilson 95% 区间下界。区间上界小于 0.6 的作业被排除；纳入待观察数据时，零评价作业获得 0.05 的权重。
- 成熟度为 `0.25 + 0.75 × min(发布后小时数 / 72, 1)`。
- 时效按 180 天半衰期衰减。质量下界达到 0.5 且有近期正面评价时，取发布年龄与评价年龄加 90 天中的较小值。评分表保存当前评价的最后修改时间。
- 曝光以同关卡、同年龄区间的对数浏览量中位数为基准，修正幅度限制在 0.9～1.1。赞踩比例的分母为好评与差评之和。

群组中相同干员、相同练度的重复条目计一次，不同技能或练度保留为不同选择，平均分配一个位置的贡献。无法解析的条目仍占据自己的份额。单成员群组也保留备选标记，关闭包含群组备选时会被排除。同一干员出现在多个群组时，只取总份额最大的群组，并保留其中的技能和练度分配；固定上场的配置优先于群组备选。

贡献先除以关卡内独立打法数，再按活动或章节和关卡类型平衡。常驻内容与其他内容分别统计分类，总预算分别为 0.3、0.7；其中一类为空时，另一类使用完整预算。质量权重在平衡后保留。

默认候选需要近期至少两个关卡、三个独立打法支持；指定关卡或活动时，一个可靠打法即可。`stageCount`、`recentStageCount` 和关卡支持门槛均按关联后的目录 `stageId` 去重，同一关卡的不同 `difficulty` 标记不增加关卡覆盖数；目录中具有不同 `stageId` 的普通与突袭变体仍各计一关。每簇取一份有效评价汇总，Wilson 下界达到 0.5 才满足置信条件。只有历史支持的干员可在历史模式查看。结果状态分为近期适用、范围有限、历史适用和反馈不足。

## 养成目标

按技能编号和模组类型划分分支，根据来源中的精英化、等级和技能等级要求构造可行配置，并满足技能和模组的解锁条件。达到分支内目标覆盖率后，只保留各维度无法再降低的配置；无法比较高低的配置并列返回。技能 8～10 级对应专精一～三。

每个分支展示需求占比、覆盖率，以及精英化与等级、技能等级、模组类型的数据完整率。来源中缺失的字段保持未知，覆盖率按已注明的需求计算。

相同需求先合并权重。小分支直接枚举覆盖，大分支按精英化阶段建立等级、技能等级的前缀和；进阶后的等级重置及未知字段分别处理。枚举同一阶段、等级时只保留首个达标的技能等级，再筛选不可降低的配置。

模组建议包含类型，`TrainingTarget.moduleLevel` / 前端 `moduleLevel` 保持为空。

## 数据和缓存

公共推荐证据保存在 PostgreSQL 的 `recommendation_snapshot` 表中，每天 00:00（`Asia/Shanghai`）在后台重建。新增、编辑、评分、浏览量、删除、转为私有、关卡同步及开放状态变化，都在下一次重建时更新，不逐次查询反馈或清空推荐缓存。当天已收录的作业在删除或转为私有后，仍可能出现在推荐来源中，直到次日重建。统计时间固定为快照生成时间，可通过 `generatedAt` 查看。表中只保留最近一次完整快照，不提供任意日期的历史归档。

构建时以 1000 条为一页读取公开且未删除的自动作业，在读取下一页前解析当前页 JSON，只累积来源必要字段、练度需求和动作指纹。中间分组对象不引用原始实体或 JSON，原始内容只保留当前页；精简中间数据仍随有效作业数量增长。全部页面统一按最早发布时间归并打法，跨页副本不会重复计权。保留完整历史来源以确定打法年龄和常驻需求，不按一年简单截断。落库前，将干员和关卡整理为各自的目录；每个打法只保留作业数、最早发布时间，以及各代表变体的来源、赞踩、浏览量、最近正面评价和练度需求。成员与关卡通过目录索引关联，不保存原始作业 JSON、动作指纹或重复副本。养成目标和筛选计数仍按原有规则计算。

大型解析和构建在临时虚拟线程中完成，线程结束后不再持有原始作业或完整证据。数据库事务锁保证多个实例同一天只构建一次，新快照写入成功后才整体替换旧快照。构建期间继续读取旧数据，失败时保留上一份完整快照，等待重试。进程重启后直接复用数据库中的证据，无需重新扫描和解析原始作业；没有可用快照时，首次请求等待构建完成。同一份证据的格式或计算含义不再兼容时，需要递增存储格式版本，触发重建。

内存缓存最多 16 组查询结果，30 分钟未访问后过期；另保留一份有效期为 1 分钟的快照版本信息，以及最多一份当天轻量关卡目录。目录通过 SQL 只读取快照的 stages 字段，用于昂贵计算前的输入校验，不加载完整证据。结果按快照时间和规范化查询区分，使用 Caffeine `get(key, loader)` 合并相同查询，命中时不加载完整证据。未命中时从数据库读取精简证据，再计算权重、曝光基线和练度目标；最多同时计算两个查询，计算结束后不缓存完整证据。新快照发布后，本实例清空旧结果，其他实例最多在 1 分钟后重新确认版本；已开始的请求仍使用取得的证据。

读取版本时若发现快照早于当天，会在后台补建；同一实例合并并发构建，失败后的读取重试间隔由 1 分钟版本缓存控制。定时任务也会在没有快照时构建。接口响应继续使用 HTTP `no-store`。

返回的 `activities`、`stages` 已按范围和数量门槛过滤，前端直接使用 `activities`，避免从关卡元数据重新引入已排除的内部编号。`stages` 包含可选的 `category`、`activity`，供前端联动筛选。指定类型或活动时，关卡选项必须具有匹配的归属信息。页面更改用途时重置时间、类型、活动、关卡和开放状态，更改类型时重置活动和关卡，更改活动时重置关卡；本地搜索与星级、职业筛选不重新请求接口。每组先显示 30 位干员，展开后才挂载详情。切换服务器筛选时保留上次结果并显示更新状态，失败后可重试。

干员目录复用 `ArkGameDataHolder` 的游戏资源快照，从 `character_table.json` 读取干员身份、职业和星级，从 `uniequip_table.json` 读取模组类型与顺序。关卡同步和推荐服务共享快照，一天内复用，过期后按需刷新；抓取失败时保留旧快照。推荐数据快照重建时使用最新目录，更新干员数据无需生成文件或重新部署。
