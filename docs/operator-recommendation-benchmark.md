## 回放方法

在后端根目录执行。准备脚本只读来源，输出目录必须尚不存在。路径按实际缓存位置设置：

```sh
python3 scripts/prepare-recommendation-replay.py \
  --snapshot "$SNAPSHOT" \
  --summaries "$SUMMARIES" \
  --operators ../zoot-plus-frontend/src/models/generated/operators.json \
  --levels "$LEVEL_RESPONSE" \
  --output build/recommendation-replay/local

RECOMMENDATION_REPLAY_DIR="$PWD/build/recommendation-replay/local" \
  ./gradlew test --tests '*RecommendationReplayTest' -PexcludeIntegration --rerun-tasks
```

回放测试默认不运行。设置目录后自动使用 2 GiB 测试堆；结果、计时和线程分配量保存在该目录。`RECOMMENDATION_REPLAY_TIME` 可覆盖固定时间。比较不同版本时保持输入、时间和 JVM 一致；独立运行的中位数会受预热、GC 及其他进程影响，不宜与同 JVM 交替测量直接混用。

测试检查得分有限、配置非空、分支覆盖率达标、技能与模组分支份额合计为 1，以及干员和来源不重复。覆盖算法还通过 60 组固定随机样本，与穷举结果比较，覆盖未知字段、精英化等级重置、技能解锁及模组解锁。

## 前端与服务验证

前端以 PR #646 的 `f172e92` 为基线。在同一份 348 位干员的响应下，页面初始展示 60 行，`main` 内节点数由 5,369 降至 1,124，减少约 79%。该指标反映渲染规模，不等同于页面耗时。

浏览器使用真实页面和回放响应，验证详情按需挂载、来源链接、本地搜索不发请求、搜索保留已展开行、刷新中的旧结果、刷新失败后的保留与重试，以及类型、活动、关卡联动。检查了 320、375、414、768、1440 像素宽度，浅色、深色、中英文和减少动态效果设置，未发现横向溢出；未连接线上写入接口。

前端 13 个测试文件、55 项测试通过，类型检查、生产构建通过。后端常规测试共 422 项，其中未设置目录的全量回放跳过，其他 421 项通过；另单独运行全量回放。`-PexcludeIntegration` 排除外部资源集成测试。SQL 投影通过嵌入式 PostgreSQL 检查，缓存归一化、两个并发计算上限、命中缓存读取和失效隔离由服务测试检查。

前端 lint 无错误，仍有其他文件的既有警告，Vite 也提示未来默认配置加载器的兼容性。没有线上数据库压测或部署验证。
